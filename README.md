# Video Git

**Video Git** — backend-проект для версионирования видеоконтента и совместной работы над ним, вдохновлённый Git и GitHub.

Цель проекта — предоставить видеомонтажёрам удобный способ управления проектами, создания веток, отслеживания изменений видеоматериалов и совместной работы без потери предыдущих версий.

> **Статус проекта:** в активной разработке. Основная backend-функциональность постепенно реализуется.

## Возможности

### Реализовано / В разработке

- Регистрация и аутентификация пользователей с использованием JWT
- Создание проектов и управление ими
- Управление участниками проектов и контроль доступа
- Создание веток на основе существующих видеокоммитов
- Использование транзакций PostgreSQL для многоэтапных операций
- Миграции базы данных
- Окружение разработки на основе Docker

### Планируется

- Загрузка видео в S3-совместимое объектное хранилище
- История версий видео и связи между родительскими и дочерними коммитами
- Асинхронная обработка видео с помощью FFmpeg
- Извлечение метаданных видео
- Отслеживание статусов обработки коммитов
- Фоновые задачи и очереди
- Предпросмотр видео и сравнение различных версий
- Дополнительные возможности совместной работы

## Архитектура

Приложение построено с использованием слоистой архитектуры, предполагающей разделение ответственности между компонентами.

```text
HTTP-запрос
     |
     v
   Handler
     |
     v
   Service
     |
     v
  Repository
     |
     v
 PostgreSQL
```

**Handler** отвечает за обработку HTTP-запросов, получение и проверку входных данных, работу с контекстом авторизации и формирование HTTP-ответов.

**Service** содержит бизнес-логику приложения и координирует выполнение операций.

**Repository** отвечает за взаимодействие с базой данных, выполнение SQL-запросов, управление транзакциями и обработку ошибок PostgreSQL.

Также архитектура предусматривает отдельный фоновый воркер для асинхронной обработки видео.

## Основные сущности

### Проекты (Projects)

Проект представляет собой рабочее пространство для управления видеоматериалами и их версиями.

Каждый проект имеет владельца, участников и ветку по умолчанию.

Создание проекта выполняется в рамках транзакции базы данных, что позволяет согласованно создать сам проект, его начальную ветку и запись об участии владельца.

### Ветки (Branches)

Ветки позволяют видеомонтажёрам работать над разными версиями или направлениями развития видеопроекта.

Новая ветка создаётся на основе существующего, успешно обработанного коммита.

При создании ветки её HEAD указывает на выбранный коммит. Новый коммит при этом не создаётся.

Названия веток должны быть уникальными внутри одного проекта без учёта регистра символов.

### Коммиты (Commits)

Коммит представляет собой отдельную версию видеоконтента.

Коммиты связаны между собой через ссылки на родительские коммиты, что позволяет восстанавливать историю версий и отслеживать связи между ветками.

Обработка видео будет выполняться асинхронно. После завершения обработки система будет обновлять статус коммита и сохранять извлечённые метаданные.

## Целостность данных

Для обеспечения согласованности данных backend использует транзакции PostgreSQL.

Примеры операций:

- Создание проекта вместе с веткой по умолчанию и записью об участии владельца
- Проверка доступа пользователя к проекту и создание ветки
- Поддержание связей между коммитами и указателями HEAD веток

Механизмы управления конкурентным доступом и уровни изоляции транзакций являются направлениями дальнейшего развития проекта.

## Запуск проекта

## Мотивация

При работе над видеопроектами монтажёры часто используют файлы с названиями вроде `final.mp4`, `final_v2.mp4` или `final_revised.mp4`, создают копии рабочих папок и обсуждают изменения через сторонние сервисы.

Такой подход затрудняет отслеживание истории изменений и организацию совместной работы.

**Video Git** исследует возможность применения концепций систем контроля версий — коммитов, веток, истории изменений и совместной разработки — к процессу видеомонтажа.

Кроме того, проект позволяет на практике изучать backend-разработку на Go, работу с PostgreSQL, распределёнными компонентами, асинхронной обработкой задач и обеспечением целостности данных.
